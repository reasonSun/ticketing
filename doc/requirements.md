# 아이유 콘서트 티켓팅 초기 요구사항

## 1. 목표 및 범위

총 200석인 아이유 콘서트의 좌석 조회, 예매, 예매 조회, 취소 기능을 제공한다. 사용자는 원하는 좌석을 선택하고 결제 없이 즉시 예매를 확정한다.

- 초기 운영 대상은 **아이유 콘서트 1개, 공연 회차 1개**다.
- 다른 콘서트도 추가할 수 있도록 공연 정보는 공연 ID로 구분한다.
- 백엔드 API를 구현 대상으로 한다.
- 회원가입, 로그인, 결제, 좌석 임시 선점, 대기열, 관리자 화면은 제외한다.

## 2. 기본 정책

| 항목 | 정책 |
|---|---|
| 좌석 | 공연에 속한 지정 좌석 1~200번 |
| 예매 단위 | 요청당 1석 |
| 사용자별 한도 | 해당 공연의 유효한 예매 최대 1건 |
| 사용자 식별 | 미리 등록한 테스트 사용자 ID 사용 |
| 예매 확정 | 예매 요청 성공 시 즉시 확정 |
| 예매 가능 시간 | 별도 오픈 시각 없이 공연 시작 전까지 |
| 취소 | 공연 시작 전까지 본인 예매만 취소 가능 |
| 취소된 좌석 | 즉시 다시 예매 가능 |
| 취소 후 재예매 | 가능하며 새로운 예매 번호 발급 |
| 공연 시작 이후 | 신규 예매와 취소 불가, 조회는 가능 |

공연명, 공연 시작 일시, 테스트 사용자는 초기 데이터로 등록한다. 날짜와 시간의 판단 기준은 서버 시간이며, 표시 기준은 한국 시간이다.

## 3. 기능 요구사항 및 인터페이스

### 공연·좌석 조회

- 공연 목록과 공연 상세 정보를 조회할 수 있다.
- 공연 상세에는 공연 ID, 공연명, 시작 일시, 총 좌석 수, 잔여 좌석 수를 제공한다.
- 좌석 목록에는 좌석 ID, 좌석 번호, 예매 가능 여부를 제공한다.
- 다른 사용자의 개인정보와 예매 정보는 좌석 조회에 노출하지 않는다.
- 조회 시 예매 가능한 좌석도 실제 예매 요청 시점에는 다른 사용자에게 예매될 수 있다.

### 예매

- 테스트 사용자 ID와 공연 ID, 좌석 ID로 예매를 요청한다.
- 사용자·공연·좌석의 존재 여부와 해당 공연에 속한 좌석인지 검증한다.
- 이미 예매된 좌석, 사용자별 한도 초과, 공연 시작 이후 요청은 거절한다.
- 성공 시 고유 예매 번호, 공연 정보, 좌석 번호, 예매 상태, 예매 시각을 반환한다.
- 실패한 요청은 좌석이나 예매 내역에 변경을 남기지 않는다.

### 예매 조회·취소

- 사용자는 본인의 예매 목록과 개별 예매 상세를 조회할 수 있다.
- 취소된 예매도 이력으로 남긴다.
- 취소 시 예매 상태를 변경하고 좌석을 다시 판매 가능한 상태로 만든다.
- 이미 취소된 예매에 대한 취소 요청은 기존 취소 상태를 반환한다.
- 다른 사용자 ID로 해당 예매를 조회하거나 취소하는 요청은 거절한다.

테스트용 사용자 ID는 요청 헤더 `X-User-Id`로 전달한다. 실제 로그인 인증이 아니므로 사용자 ID를 신뢰하는 개발·학습 환경을 전제로 한다.

| API | 역할 |
|---|---|
| `GET /concerts` | 공연 목록 조회 |
| `GET /concerts/{concertId}` | 공연 상세 조회 |
| `GET /concerts/{concertId}/seats` | 좌석 목록 조회 |
| `POST /concerts/{concertId}/reservations` | 본문의 `seatId`로 예매 |
| `GET /reservations` | 요청 사용자의 예매 목록 조회 |
| `GET /reservations/{reservationId}` | 본인의 예매 상세 조회 |
| `POST /reservations/{reservationId}/cancel` | 본인 예매 취소 |

잘못된 입력은 400, 타인의 예매 접근은 403, 존재하지 않는 대상은 404, 중복 예매·한도 초과·시간 제한 위반은 409로 응답한다. 오류 응답에는 구분 가능한 오류 코드와 설명을 포함한다.

## 4. 데이터 및 정합성 요구사항

- 기본 데이터는 사용자, 공연, 좌석, 예매로 구성한다.
- 좌석 번호는 공연 내에서 유일하며, 초기 공연에는 정확히 200석을 등록한다.
- 예매 상태는 `CONFIRMED`와 `CANCELED`로 구분한다.
- **같은 좌석에 유효한 예매는 최대 1건**만 존재해야 한다.
- **같은 사용자의 해당 공연 유효 예매는 최대 1건**만 존재해야 한다.
- 동시 요청에서도 두 조건을 보장하고, 유효 예매 총수는 200건을 넘지 않아야 한다.
- 예매 확정과 좌석 확보, 예매 취소와 좌석 반환은 각각 하나의 트랜잭션으로 처리한다.
- 서버 재시작 후에도 예매 및 취소 이력을 유지한다.

## 5. 완료 기준

- 초기 좌석 조회에서 200석 모두 예매 가능 상태로 표시된다.
- 정상 예매 성공 후 해당 좌석은 예매 불가 상태가 되고 잔여 좌석 수가 1 감소한다.
- 여러 사용자가 같은 좌석을 동시에 요청하면 정확히 1건만 성공한다.
- 같은 사용자가 서로 다른 좌석을 동시에 요청해도 정확히 1건만 성공한다.
- 200명의 사용자가 각각 다른 좌석을 예매하면 잔여 좌석은 0이 된다.
- 본인 예매 취소 후 잔여 좌석이 복구되고, 취소한 사용자와 다른 사용자 모두 해당 좌석에 다시 예매를 시도할 수 있다.
- 반복 취소로 잔여 좌석 수가 중복 증가하지 않는다.
- 타인의 예매 접근, 잘못된 대상, 공연 시작 시각 이후의 예매·취소가 거절된다.
- 동시성 검증은 실제 운영 DB와 같은 MySQL 환경에서 수행한다.

처리량과 응답 시간의 수치 목표는 이번 초기 버전에서 정하지 않는다. 우선 기능과 중복 예매 방지의 정확성을 완료 기준으로 삼는다.
